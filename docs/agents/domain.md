# Domain Docs

Engineering skills should read the root `CONTEXT.md` and relevant records in `docs/adr/` before exploring or changing this single-context repository.

## Before exploring, read these

- `CONTEXT.md` at the repo root
- Relevant records in `docs/adr/`

If any of these files do not exist, proceed silently. Do not flag their absence or suggest creating them upfront.

## Use the glossary's vocabulary

When output names a domain concept, use the term defined in `CONTEXT.md`. If the needed concept is missing, reconsider the wording or note the gap for domain modeling.

## Flag ADR conflicts

If output contradicts an existing ADR, surface that conflict explicitly rather than silently overriding it.
